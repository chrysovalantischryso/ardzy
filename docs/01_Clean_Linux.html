Clean Linux: a fresh Debian 12 for the board

The first, simple step: replace the big old system on the SD card with a small, clean Debian, while keeping the boot files that are proven to work.

1. Why this step

The board was running ADI Kuiper Linux (Debian 11), a big system made for Analog Devices radio boards. It used 9.9 GB and was full of programs you do not need. The goal: a clean system that is small, current, and only yours.

Earlier, a PetaLinux image did not start on this board, and there was no serial cable to see why. So this step takes the safe road: reuse the boot files that already work, and replace only the operating system.

2. What was done

  1. Looked at the running board over SSH: kernel 5.15.19 (Xilinx), all drivers built into the kernel (no module folder), SD card with a FAT boot partition and an ext4 system partition.
  2. Copied the 4 proven boot files from the board: BOOT.bin, uImage, system.dtb, uboot.env.
  3. Checked the kernel supports what Debian 12 needs (systemd: cgroups, devtmpfs, inotify, seccomp...) and what FPGA work needs (FPGA manager, device-tree overlays, UIO). All present.
  4. Built a fresh Debian 12 system on the PC (in WSL Ubuntu) with debootstrap for the ARM processor (armhf), running the ARM programs through the QEMU emulator.
  5. Configured it: name tx (so tx.local keeps working), network, SSH, first-boot setup, clock.
  6. Packed everything into one SD card image (2 GB) and tested it in an emulated Zynq board.

4. How it was built

Everything is in one script, build_clean_debian.sh, run inside WSL (Ubuntu 20.04) as root:

debootstrap --arch=armhf  bookworm  rootfs/      # download + unpack Debian for ARM
chroot rootfs  (via qemu-arm-static)              # run ARM setup commands on the PC
mkfs.vfat + mcopy   -> boot partition             # no loop devices needed
mkfs.ext4 -d rootfs -> root partition
sfdisk + dd         -> antminer_s9_debian12.img
Small trick Ubuntu 20.04's own debootstrap is too old to know Debian 12, so the script downloads Debian's newer debootstrap and keyring and uses them directly.

5. How it was tested

The image was started in QEMU, which can pretend to be a Zynq-7000 board. The board's own kernel and device tree were used.

  • Result: boots to tx login:, SSH login works, 0 failed services, Python, numpy and gcc run. passed
  • Found on the way: the board's console is on UART1 (not UART0). This matches the real board.
  • Found in a later check and fixed: the DNS setting had been copied from the build PC (a WSL-only address), so internet names would not work on the board. Now systemd-resolved takes the DNS server from the router. Tested: names resolve, apt update works, the clock syncs. passed
  • Not testable in an emulator: the real Ethernet chip and the FPGA. They use the same kernel and drivers as the working old card.

6. Flash and use it

  1. Use a second microSD card (keep the old one as a backup).
  2. balenaEtcher: Flash from file → antminer_s9_debian12.img → the SD card → Flash. If Windows asks to format the card, click Cancel.
  3. Board off, insert the card, power on, wait about 2 minutes.
  4. PuTTY → tx.local → login root / root. Accept the new host key once. Then passwd.

8. Limits (and why Ardzy came next)

Not fully clean The operating system is new, but the boot files are not ours: an old kernel (5.15) from the Kuiper card, a device tree that still describes the FM design, and a BOOT.bin that loads the FM "TEST" design into the FPGA at every power-on.

Project 2, Ardzy, builds every part from source, starts with an empty FPGA, and adds the "Arduino-style" upload system.
