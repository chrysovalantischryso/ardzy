Ardzy: flash, boot, use, and the UART console

Everything from an empty microSD card to your first program on the board, step by step. Also how the board starts, what the LEDs mean, how to use the serial console (UART) with a USB-UART adapter, how to update safely, and what to do when something does not work.

1. What you need

  • The Antminer S9 control board (Zynq XC7Z010).
  • A 12 V power supply for J14 (the 6-pin PCIe-style connector) or J15 / J16. A PC power supply or any 12 V brick of 1 A or more is fine: the board alone takes much less.
  • A microSD card, 4 GB or bigger. The image is 2.5 GB and grows to fill the card at the first start.
  • A microSD card reader for the PC.
  • A Windows PC (10 or 11) for the Ardzy app.
  • One way to talk to the board (both is best):
    • an Ethernet cable, to your router or straight to the PC, and/or
    • a 3.3 V USB-UART adapter (CP2102, CH340, FT232) and 3 jumper wires. J12 is often not soldered: you may need a 3-pin 2.54 mm header.

.img is not .iso. The SD card file is a disk image (.img, packed as .img.xz). You do not copy it onto the card like a normal file and you do not "burn" it like an ISO: a writer program writes it to the card byte by byte. You do not need to unpack the .xz first: the Ardzy app and balenaEtcher read it as it is.

To check a download is complete, in PowerShell:

Get-FileHash .\Ardzy-0.3.1-sdcard.img.xz      # compare with the line in SHA256SUMS.txt

Install the app: run Ardzy-0.3.1-BETA-Setup.exe. It installs for your user only (no admin needed) into %LOCALAPPDATA%\Programs\Ardzy. If Windows SmartScreen says "Windows protected your PC": More info, Run anyway (the program is not signed).

3. Flash the SD card

Writing an image erases the whole card. Copy anything you want to keep off it first. Both ways below only show removable cards (1 to 256 GB), so your PC's own disks are not in the list, but still check the size before you click Write.

Way A (easiest): the Ardzy app

  1. Put the microSD card in the PC's card reader.
  2. Start Ardzy and click SD card in the header. The "Write an SD card" window opens.
  3. 1. Board and system image: Board = Antminer S9, Choose file: Ardzy-0.3.1-sdcard.img.xz.
  4. 2. microSD card: choose your card (check the size; Refresh if you put it in after opening the window).
  5. Set the board settings: board name (default ardzy), a new root password, the network ("automatic" is right for almost everyone), the time zone, SSH, and what to load at power-on. The app writes them into ardzy.txt on the card (see section 4).
  6. Leave "check the card after writing (recommended)" ticked and click Write card. Windows asks for administrator permission (writing a whole disk needs it). It takes a few minutes.
  7. The app reads the card back and compares it. Wait until it says the card was written and checked.
  8. If Windows pops up "You need to format the disk in drive X: before you can use it": click Cancel. That is the Linux partition, which Windows cannot read. Never format it.
  9. Take the card out.

Way B: balenaEtcher (or any image writer)

  1. Install balenaEtcher from etcher.balena.io.
  2. Flash from file: Ardzy-0.3.1-sdcard.img.xz.
  3. Select target: your microSD card (check the size!).
  4. Flash. Etcher checks the card itself afterwards.
  5. Windows "format the disk?" pop-up: Cancel.
  6. Optional: open the small FAT drive that appears (the boot partition) and edit ardzy.txt with Notepad (name, password, network).

What is on the card

4. Board settings: ardzy.txt

A plain text file on the boot partition. The app writes it when it makes a card, and changes it live when you change settings in the app. You can also edit it on the PC with Notepad. It is applied at every boot when it changed.

hostname = ardzy
password =
network  = auto
timezone = Europe/Athens
ssh      = on
at_boot  = pin-control
KeyValuesDefaultWhat it does
hostnameletters, digits, -ardzyBoard name on the network: <hostname>.local
passwordany text(empty)New root password. Applied once at the next boot, then erased from the file so it is not left in plain text.
networkauto / static / linklocalautoauto = DHCP from a router, or link-local when there is none (direct cable to a PC)
address, gateway, dns192.168.1.50/24, 192.168.1.1, 1.1.1.1(empty)Only with network = static
timezoneEurope/Athens, UTC, ...UTCBoard clock time zone. The app also sets the board's clock when it connects (the board has no clock battery).
sshon / offonSSH login (PuTTY)
at_bootpin-control / none / a project namepin-controlWhat goes into the FPGA at power-on: the pin-control design (I/O view, Arduino sketches), nothing, or one of your projects

The board's MAC address (its network ID) is chosen at the first start and then kept in uboot.env, so your router always sees the same board.

5. Boot jumpers: SD card or the original firmware

Four 3-pin jumpers JP1 to JP4 tell the chip where to boot from. They are read only at power-on. For Ardzy, JP2 = 1 and JP4 = 1 (JP1 and JP3 = 0). For the original Bitmain firmware in the NAND chip, only JP2 = 1.

Boot fromJP1JP2JP3JP4Notes
microSD card (Ardzy)0101Use this
NAND flash (original Bitmain firmware)0100Ardzy never writes the NAND, so the original firmware is still there
JTAG only0000For Vivado Hardware Manager
If you are not sure about the jumpers: a wrong setting does no harm. The board simply does not start from the card (no text at all on the UART console, see troubleshooting). Change the jumpers only with the power off.

6. Power on and boot

  1. Power off. Card in the microSD slot J11 (contacts down, it clicks in).
  2. Plug in the Ethernet cable and/or the USB-UART adapter (section 9).
  3. Plug in 12 V. The power-good LED D15 lights at once.
  4. Wait. A normal start takes about 30 to 40 seconds. The first start takes about 2 minutes: it makes the SSH keys, grows the root partition to the whole card, chooses and saves the MAC address, and applies ardzy.txt.
  5. The bicolor LED D3 turns green: Ardzy is ready.

What happens inside, in order

The FPGA is empty until step 6. When the design is loaded the FPGA DONE LED D1 lights. 90 seconds after the start the board writes "boot OK" (used by safe mode and safe kernel updates, section 14).

8. Connect from the PC

Over the network

Two ways to cable it. Both work with no settings:

CableWhat the board getsHow the app finds it
Board to your router (same network as the PC)An IPv4 address from the router (DHCP)By itself; also ardzy.local
Board straight to a PC Ethernet portLink-local addresses (IPv4 169.254.x.x and IPv6 fe80::...)By itself over IPv6 link-local; also ardzy.local
  1. Start Ardzy. In a few seconds the board button (top right) shows your board as connected.
  2. If not: click the board button, Scan again, or type ardzy.local (or the IP address your router shows) under "Or connect by name / IP" and Connect.

Without the app:

  • Browser: http://ardzy.local (the board's own web page).
  • SSH: PuTTY, host ardzy.local, port 22, login root, password root (or the one you set). Or in PowerShell: ssh root@ardzy.local
Change the password if it is still root and the board is on a network others use: type passwd on the board, or set it in the app's board settings.

Over the USB-UART cable (no network needed)

Wire the adapter to J12 as in section 9, then in the app: board button (top right) → Or over a USB-UART cable → choose the COM port → Connect over cable. The app logs in on the console, starts a small link program on the board and switches the line to 921600 baud by itself (about 87 KB/s). Everything works over it: upload, Monitor, I/O, Terminal. When the app disconnects, the normal login prompt comes back.

9. The UART console on J12

J12 is the board's serial console (Zynq UART1, Linux ttyPS0). It shows every boot message from the very first line, and gives you a login prompt. It is the best tool when something does not start, and it works with no network at all.

Wiring

3.3 V only. If your adapter has a 5V / 3V3 jumper, set it to 3V3. A 5 V signal can damage the level shifter on the board. RS-232 (a real COM port on the back of a PC, like COM1) is not 3.3 V and must not be connected directly.

Settings

Speed115200 baud
Format8 data bits, no parity, 1 stop bit (8N1)
Flow controlNone
PortWindows Device Manager → Ports (COM & LPT) shows it, for example "Silicon Labs CP210x ... (COM3)". CH340 may need its driver from the maker.

Three ways to use it

ToolHowBest for
Ardzy app, bottom tab USB serialChoose the COM port (Refresh ports if it is new), 115200, OpenWatching the boot log, logging in by hand
Ardzy app, cable linkBoard button → Or over a USB-UART cable → Connect over cableUsing the whole app without a network
PuTTYConnection type Serial, Serial line COM3, Speed 115200, Open. Press Enter once.A plain terminal, the U-Boot prompt

Only one program can open a COM port at a time: close PuTTY before the app uses the cable, and the other way round.

First test

  1. Board powered off. Wire the adapter, plug it into the PC, open the port at 115200.
  2. Power on the board. Within a second you should see U-Boot SPL 2026.07.
  3. When it stops at ardzy login:, type root, Enter, then the password.
  4. Try: ardzy status, ip addr (shows the board's IP addresses), ardzy beep.

Long lines wrap strangely? The serial line does not know your window size: type stty cols 120 rows 40 (your window's size).

10. The U-Boot prompt (advanced)

When the console shows Hit any key to stop autoboot: 2, press any key within 2 seconds. You get the boot loader's prompt ardzy-s9>. It is only needed for repairs and curiosity; normal use never needs it.

CommandWhat it does
bootContinue the normal start
printenvShow the settings (uboot.env), for example the MAC address and the update flags
mmc info, ls mmc 0:1Is the card seen? Which files are on the boot partition?
bdinfoMemory size and addresses
resetRestart the board
Do not use saveenv, env default or any nand command unless you know why. saveenv after changing things can change the MAC address or the update state; nand erase destroys the original Bitmain firmware.

11. The other UART: Serial1 on the connector pins

Not the same as J12. Serial1 is a UART inside the FPGA (pin-control design) for your own programs: GPS, ESP32, Arduino, a serial module, a PC terminal. Default pins: TX = J1 pin 11, RX = J1 pin 12, GND = J1 pin 9; any other connector pins with Serial1.setPins(rx, tx). Any speed (tested 9600 to 1 000 000 baud).

void setup() {
  Serial1.begin(9600);          // the FPGA UART on J1 pins 11 / 12
  Serial.begin(115200);         // "Serial" = the app's Monitor tab
}
void loop() {
  while (Serial1.available()) Serial.write(Serial1.read());   // show what the device sends
}

Ready examples in the app (Code view → Examples): UartLoopback (test with no wire at all), UsbUartAdapter, ArduinoLink, ESP32Link, GPSReader. The Tools view also has a UART terminal on any pins. Full wiring for each device: document 8, How to connect things.

12. Use it: your first programs

Blink an LED (Arduino C++)

  1. Code view → Examples → 01.Basics → Blink (or a new project of your own).
  2. Click Upload (Ctrl+U). The board compiles it (a few seconds), loads the pin-control FPGA design, and runs it. The first FPGA LED (LED0, LED_BUILTIN) blinks.
  3. Output of Serial.print shows in the bottom tab Monitor; numbers draw in Plotter; name:value lines in Watch.
  4. Stop ends the program. Upload again after any change.

Start a project at power-on

In the app: tick at boot next to Upload, or on the board ardzy load myproject --default. Back to normal: untick it, or ardzy default none.

14. Updates and safe mode

Update without re-flashing

App: System view → Settings and update → choose Ardzy-0.3.1-update.tar.gz. Your projects and settings stay. Most updates need no restart. On the board the same is ardzy update Ardzy-0.3.1-update.tar.gz.

A new kernel that does not start goes back by itself

When an update brings a new Linux kernel, the old one is kept as zImage.old. The first start of the new one is a trial: if the board does not reach "boot OK" (90 seconds after the start), the next start uses the old kernel again and the console says Ardzy: the new kernel did not start last time: using the previous one.

Safe mode

If your at_boot project hangs the board, the boot never reaches "boot OK". At the next start Ardzy does not load that project, D3 is red, and ardzy status says SAFE MODE. Fix the project, then ardzy load <name> (that also ends safe mode). So a bad project can never lock you out.

Re-flash

Writing the card again (section 3) always gives a fresh board. It erases your projects on the card: copy them first (they are also in your workspace on the PC if you made them in the app).

15. Turn it off

The card is written to while Linux runs. Pulling the power during a write can damage files. Best:

  1. App: Board view → System card → Power off, or on the board: poweroff.
  2. Wait about 10 seconds (the console says reboot: Power down).
  3. Unplug 12 V. After Power off the board stays off until you switch the 12 V off and on again.

Restart instead: Reboot board in the same card, or reboot.
