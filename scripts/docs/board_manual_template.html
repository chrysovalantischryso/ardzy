4. The Zynq XC7Z010

The Zynq-7000 is an SoC: a fixed ARM processor system (PS) and an FPGA (PL) on one die. The PS boots first and is in charge; the PL is configured afterwards (by the boot loader or, in Ardzy, by Linux).

Processing System (PS)

CPU2 × ARM Cortex-A9 MPCore (ARMv7-A), NEON SIMD and VFPv3 floating point. On this board: 666.7 MHz (ARM PLL 1333.3 MHz / 2), clock ratio 6:2:1
Caches32 KB instruction + 32 KB data L1 per core, 512 KB shared L2, Snoop Control Unit (cache coherency)
On-chip memory256 KB OCM (the first boot stage runs here; BootROM loads at most 192 KB)
Memory controllerDDR3/DDR3L/DDR2/LPDDR2, 16 or 32 bit. Here: DDR3, 32 bit, 533.3 MHz (DDR3-1066)
Static memory controllerNAND (used: 8-bit NAND on MIO 0-14) or parallel NOR/SRAM
Peripherals (2 of each)Gigabit Ethernet (GEM), USB 2.0 OTG, SD/SDIO, UART, SPI, I2C, CAN. Used here: GEM0, SDIO0, UART1, I2C1 (pins MIO28/29)
GPIO54 MIO pins + 64 EMIO lines to the FPGA (Linux: gpiochip0, 118 lines, line number = MIO number)
Timers2 triple timer counters (TTC), global timer, private timers, 1 system watchdog (SWDT, used by Ardzy with 30 s) + private watchdogs
DMA8-channel DMA controller (PL330)
InterruptsGIC (generic interrupt controller), 16 interrupt lines from the FPGA (IRQ_F2P)
SecurityAES-256 / HMAC secure boot, eFuses (not used here; battery input VCCBATT tied to ground)
XADC12-bit 1 MSPS ADC with temperature and supply sensors (Linux: iio:device0). The external analog inputs are not wired on this board.
Config interfacePCAP / devcfg (200 MHz): how the PS loads FPGA designs (Linux FPGA manager)

10. Reset and boot

Reset

  • Power-on reset (PS_POR_B, pin C7) is held until the 3.3 V regulator reports power good (P_GOOD). The same signal resets the Ethernet PHY.
  • PS_SRST_B (pin B10) comes from JTAG J10 pin 14 through level shifter U2. Button S1 is not wired to it (its resistor R24 is not fitted): S1 is a normal input on MIO47.
  • Linux restarts the board through the SLCR (software reset). The watchdog (SWDT) can also reset it.

Boot sequence (SD card)

  1. BootROM (inside the chip) reads the straps, starts the SD controller at a slow clock, and looks for BOOT.bin on the first FAT partition. MIO0 (NAND CE#) must read low during SD boot; a 20 kΩ pull-down takes care of it.
  2. It checks the boot header (XNLX marker) and copies the first stage (max 192 KB) into on-chip RAM.
  3. SPL / FSBL writes the ps7_init tables: pin mux (MIO), PLLs and clocks, DDR3 timing, peripheral setup, then enables the PS-PL level shifters.
  4. It loads U-Boot (u-boot.img) into DDR. U-Boot reads uboot.env, runs boot.scr, loads zImage and system.dtb, and starts Linux.

12. NAND flash

PartMicron MT29F2G08AACWP (U5), TSOP-48, 3.3 V
Size2 Gbit = 256 MB, SLC, 8-bit bus; 2 KB pages + 64 B spare, 128 KB blocks, 2048 blocks
ConnectionPS static memory controller on MIO 0-14 (table in chapter 17). CE#, WP#, R/B# have 1 kΩ pull-ups
Contentthe original Bitmain firmware (boot loader, Linux, mining software). Untouched by Ardzy.
In Ardzyvisible as one read-only partition "bitmain-nand" (/dev/mtd0, /dev/mtd0ro): it can be scanned and backed up, never written
Write protectionthree layers: (1) read-only partition in the device tree; (2) the full chip is not exposed (no master device); (3) kernel patch: the Zynq NAND driver normally forces an on-flash bad-block table and would write one to the chip if it does not find one. Ardzy's kernel builds the table in RAM by only reading the factory bad-block markers.
Toolsmtdinfo, nanddump (mtd-utils); Ardzy app → Board → NAND card: scan contents, backup "data" (256 MB, ECC corrected) or "exact raw copy" (with the 64 spare bytes of every page and bad blocks, 264 MB)
Boot from itjumpers: JP2 = 1, all others 0 (the board then starts the original firmware)
Back it up once The NAND holds the only copy of the original Bitmain firmware. Make an "exact raw copy" backup with the Ardzy app and keep it with its .sha256 file.

22. Limits and safety

  • FPGA pins: 3.3 V maximum. No 5 V signals (use a level shifter). Drive strength up to 16 mA per pin (default 12 mA); keep the total small.
  • EN pins (MIO28-36) are 2.5 V outputs: fine for 3.3 V logic inputs, too weak for anything else.
  • Connector pin 16 (3.3 V) shares the 2 A board regulator: small sensors only.
  • Board ID pins: fixed straps, never drive them.
  • 12 V input: use a regulated 12 V supply. The regulators accept up to 17 V, but the 15 V protection diode (D16) starts conducting near 16.7 V, so stay at 12 V.
  • Temperature: the chip is rated 0 to 85 °C (junction). At about 48 °C idle it has margin; big designs at high clock speed need airflow (a 12 V fan on FAN1 works).
  • Empty FPGA addresses: reading or writing an address where your design has nothing freezes the bus; the watchdog then resets the board.

23. Open questions

  • Exact DDR3 part number on U3/U4 (2 Gbit, but which one): read the chip marking.
  • Which LED number (D5-D8) is at which FPGA pin on the board, and the exact position of pin 1 on J1-J9: check visually.
  • TP1 "CLOCK_OUT" is on pin K18 according to the schematic text; confirm with a scope before relying on it.
  • The A0-A2 strap values of each hash connector (fixed per slot).
  • The NAND partition layout of the original firmware: use the app's NAND scan after the kernel update.
  • Power consumption of the board (not measured).
  • The watchdog reset on a real freeze (reset mode is active; the test is waiting for your OK).
