1. The idea

With an Arduino you write a sketch, press Upload, and it runs. Ardzy gives the Zynq board the same feeling, but you can send two kinds of things at once: a program for the ARM processors and a hardware design for the FPGA.

ArduinoArdzy
Arduino IDEArdzy app (Ardzy.exe) on Windows
Sketch (.ino)Project folder: .bit FPGA design + main.py or main.c
Upload over USBUpload over Ethernet (USB-UART console also available)
Serial MonitorMonitor tab: everything your program prints, live
BootloaderU-Boot + Linux (Debian 13) on the SD card
Sketch stays after power-offTick at boot: the project loads at every power-on
Fixed chipThe FPGA is rebuilt for every project: your own hardware

4. How it was built

Problems found and solved on the way

ProblemSolution
Which DDR settings are right for this board?A script (fsbl_to_ps7init.py) reads all 194 register writes out of the FSBL that boots the board today, and writes them 1:1 into U-Boot's file. Compared with the Vivado file: only 2 differ (see the hardware guide).
Official U-Boot has no boot command for this boardFound by testing in the emulator. Fixed twice: built into U-Boot, and in uboot.env (also used by the fallback loader).

5. What happens when you press Upload

Details worth knowing:

  • Device-tree overlay: a small add-on to the hardware description. Ardzy makes one per project. It says "program the FPGA with this file" and, if you have a devices.dtsi, adds Linux devices for your FPGA blocks. Removing it removes those devices.
  • .bit to .bin: Vivado's .bit has a text header and the wrong byte order for the Zynq loader. Ardzy converts it. The result was checked byte by byte against Xilinx's own bootgen tool: identical (bootgen only adds one extra "no operation" word at the end).
  • Chip check: every bitstream carries the chip ID it was made for. Ardzy refuses files made for another chip (for example a 7Z020 file), which earlier caused confusion.

How the app finds the board

  1. It sends a short message ARDZY_DISCOVER as a broadcast on every network card of the PC (UDP port 41414). This also covers a direct cable (169.254.x.x addresses, no router).
  2. It sends the same message over IPv6 (multicast ff02::1) on every network card. IPv6 link-local addresses (fe80::...) exist on every cable without any setup, so this works even when the PC's cable port has a fixed IPv4 address that does not match the board (for example 192.168.137.1 left over from Windows Internet Connection Sharing). This is how your board is reached today.
  3. Every Ardzy board answers with its name, IP, system and FPGA state.
  4. It also tries the remembered board and names like ardzy.local directly (works through routers).
  5. One board found: it connects by itself. Several: you choose.

Inside the app, the window talks to a small engine on 127.0.0.1 with a secret key that changes at every start, so web pages cannot control your board through it.

7. A project, file by file

Only one program runs at a time: the order is run.sh, then main.py, then Makefile, then *.c.

The two examples

blink FPGA only. A 30-bit counter on the 100 MHz clock; its top 4 bits (inverted, the LEDs are active low) drive the LEDs, so they count in binary about 1.5 times per second. main.py only prints a message.
leds_python FPGA + Python. An AXI GPIO block at 0x4120_0000 drives the LEDs. main.py writes a "Knight Rider" pattern (one LED lit, moving). Change the pattern, Upload, see it at once.
board_hello No FPGA. The red/green status LED blinks; the IP button beeps, the Reset button ends the program. Uses led(), beep(), button().

8. Making your own FPGA design

  1. Part: xc7z010clg400-1. Any other part will be refused by the chip check.
  2. Block design: add a ZYNQ7 Processing System block. No board preset is needed: DDR and pin settings in Vivado are ignored, the SD card's boot loader already set them.
  3. Clock: use FCLK_CLK0 (100 MHz). Need another frequency? Add a Clocking Wizard after it.
  4. Registers: enable M_AXI_GP0, connect your AXI blocks, read their addresses in the Address Editor (they start at 0x4000_0000).
  5. Pins: copy lines from projects\leds.xdc or the pin table in the hardware guide. Always IOSTANDARD LVCMOS33.
  6. Generate Bitstream, then Upload in Ardzy: it finds the newest .bit in the project folder by itself.
Tip Put the Vivado project inside the Ardzy project folder. Then you never have to copy .bit files by hand.

9. Programs: Python and C

Python

import time
from ardzy import MMIO, UIO, fpga_state

regs = MMIO(0x41200000)          # base address from the Address Editor
regs.write(0x4, 0)               # AXI GPIO: direction = outputs
regs.write(0x0, 0b1010)          # LEDs 1 and 3
print(regs.read(0x0))

irq = UIO("my_ip")              # needs devices.dtsi (below)
count = irq.wait()               # sleeps until the FPGA raises its interrupt

devices.dtsi for an interrupt from the FPGA (interrupt line 0 of IRQ_F2P = GIC number 29):

my_ip@43c00000 {
    compatible = "generic-uio";
    reg = <0x43c00000 0x10000>;
    interrupt-parent = <&intc>;
    interrupts = <0 29 4>;
};

C

#include <fcntl.h>
#include <stdint.h>
#include <sys/mman.h>
int fd = open("/dev/mem", O_RDWR | O_SYNC);
volatile uint32_t *gpio = mmap(0, 0x10000, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0x41200000);
gpio[1] = 0;        /* direction: outputs */
gpio[0] = 0x5;      /* LEDs 0 and 2 */

Python has numpy for fast maths. print()/printf() output goes to the Monitor (C: call setvbuf(stdout, NULL, _IOLBF, 0) so each line appears at once).

10. On the board: commands and web page

Everything the app does also works from a terminal (PuTTY, ardzy.local, root):

ardzy list                  projects on the board
ardzy load blink            program the FPGA + start the program
ardzy load blink --default  ... and again at every power-on
ardzy status                what is loaded and running
ardzy log -f                program output, live (Ctrl+C to quit)
ardzy stop / ardzy restart  the program
ardzy default none          nothing at boot
ardzy peek 0x41200000 4     read 4 registers
ardzy poke 0x41200000 5     write a register
ardzy bitinfo file.bit      which chip a bitstream is for
ardzy new test              empty project with a main.py
ardzy beep 0.2              buzzer
ardzy led red on            status LED (green | red | ps, on | off)
ardzy buttons -w            watch the IP / Reset buttons

There is also a web page at http://ardzy.local (any browser, also a phone) with upload by drag and drop, project list, live output and registers.

11. Safety features

FeatureWhat it protects you from
Chip ID checkLoading a bitstream made for another chip
Hardware watchdog (30 s)A design or address that freezes the board: it reboots by itself (reset mode confirmed active; a real freeze test is still to be done with your OK)
Status LEDGreen = Ardzy ready, red = safe mode: you see the state without a PC
Safe modeIf the board crashes while starting the "at boot" project, the next start skips that project, so you can always get back in. Load any project to leave safe mode
Clear before uploadOld files of a project never stay behind
Fallback boot loader on the cardA new boot loader that does not start on real hardware (see Troubleshooting)
Know this Reading or writing an FPGA address where your design has nothing makes the AXI bus wait forever and the board freezes. The watchdog reboots it after about 30 seconds. Use only addresses from the Address Editor. The board's web page and API have no password: use it only on your own network.

13. First start, step by step

The file to flash 2_Ardzy\out\release\Ardzy-0.2-sdcard.img.xz (compressed; the first one, 0.1, is out\Ardzy-0.1-sdcard.img.xz). The Ardzy app's SD card button writes it and checks the card (see Ardzy 0.2, Writing an SD card); balenaEtcher and Rufus flash it directly too, no need to unpack. Next to it: HOW_TO_FLASH.txt and SHA256SUMS.txt (to check the file). The same image unpacked is 2_Ardzy\out\ardzy_debian13.img. Note: for SD cards the right format is a disk image (.img), not an .iso (that is for CDs/DVDs and PC installers).
  1. Write Ardzy-0.2-sdcard.img.xz to a spare microSD card (4 GB or more) with the app's SD card button or balenaEtcher. Keep your current card as a backup.
  2. Boot jumpers on SD (JP2 and JP4 on). Ethernet cable to the PC or router. Power on.
  3. Wait about 2 minutes (the first start makes SSH keys and enlarges the partition).
  4. Open Ardzy (the shortcut). It should find ardzy by itself. Otherwise click Scan.
  5. Choose blink, press Upload: the 4 LEDs start counting.
  6. Choose leds_python, Upload. Change the pattern in main.py, Upload again.

14. Troubleshooting

SymptomWhat to do
Board never appears (no ardzy.local after 3 minutes)Use the fallback: put the SD card in the PC, rename BOOT.bin → BOOT_new.bin and BOOT_fallback.bin → BOOT.bin, try again. If that works, the new first stage needs a fix: tell Claude, and connect a USB-UART to see the messages
Best way to see what is wrongA 3.3 V USB-UART adapter on J12 (board TX → adapter RX, RX → TX, GND → GND). Ardzy app → USB serial tab → choose the COM port → Open, then power on the board: you see every boot message
Ping to the board's 169.254.x.x address failsNormal if the PC's cable port has a fixed IPv4 address (yours: 192.168.137.1). Ardzy, the web page (http://ardzy.local) and PuTTY (ardzy.local) use IPv6 then and work anyway. Optional: give the board internet by switching on Windows Internet Connection Sharing on the phone/internet adapter, shared to "Ethernet"
Scan finds nothing, but the board is onWindows firewall may block the answer: allow Ardzy when Windows asks. Or type the IP / ardzy.local in the board list
"bitstream is for 7z020..."The design was made for another chip. In Vivado set part xc7z010clg400-1
Board freezes after Upload and rebootsThe design or program touched an address with nothing behind it, or the design hangs the bus. Watchdog reboot; if it was the "at boot" project, safe mode skips it next time
Program output missingPython: fine by default. C: add setvbuf(stdout, NULL, _IOLBF, 0);
Build FPGA failsCheck the Vivado path in Settings. Open the project in Vivado for the full report
